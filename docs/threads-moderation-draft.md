# 스레드 콘텐츠 검사 — 격리 작업 초안

상태: 조사·설계 단계. 실제 업로드 경로 연결 및 모델 추론 검증 전.
작업 브랜치: `codex/threads-moderation`
기준 커밋: `a4e3eb299d94fea90818c81b25f8f3fae2b111c3`
후속 설계 이슈: https://github.com/lovesangmin716-hue/free-danny-chat/issues/33

## 작업 경계

사용자의 최신 요청에 따라 현재 배포에 영향을 주지 않도록 별도 워크트리에서 준비한다.
기존 체크아웃의 미커밋 작업을 복사하거나 변경하지 않는다.
이 초안은 런타임 코드, 환경 변수, 의존성, 운영 DB, 배포 설정을 변경하지 않는다.
실제 모델 연결은 아티팩트와 입력/출력 계약을 검증한 후 후속 변경으로 진행한다.
향후 코드가 연결되더라도 기본 상태는 off이며, 운영 활성화는 별도의 검증 단계다.

## 확정한 구조

1. 임베딩 검색으로 기존 글·기사와 이전 맥락 왜곡 차단 기록의 비교 후보 확보.
2. 하나의 통합 모델이 한 번의 추론에서 제목/본문 맥락 왜곡과 중복·단순 재작성 및 차단 내용 재업로드를 함께 판정.
3. 독립된 KAIST 연구 모델 어댑터로 분란 조장 관련 신호 검사.
4. 필수 검사를 통과한 글만 공개 저장하고 알림 생성.
5. 피드에서는 최근 노출한 유사 내용의 포화를 반영해 노출 순위/확률 조정. 업로드 차단에 사용하지 않음.

통합 모델/검색 엔진과 피드 기능은 #33에서 추적한다.
우선 언어는 한국어·영어이며, KAIST 한국어 체크포인트의 영어 지원을 가정하지 않는다.

## KAIST 공개 결과물 확인

논문: Cross-National Information Attacks: A Two-Decade Analysis of Troll Behavior in Korea
- https://www.usenix.org/conference/usenixsecurity26/presentation/kim-jaehong
- https://arxiv.org/html/2606.22785v1
- 공개 아티팩트 DOI: https://doi.org/10.5281/zenodo.20257085
- API에서 연결된 파일 버전: https://zenodo.org/records/21348299
- 아티팩트 README: https://zenodo.org/api/records/21348299/files/README.md/content

아티팩트 메타데이터 및 README에서 확인한 내용:
- `code.zip`: 2,820,120,047 bytes. 추론 코드·체크포인트·분석용 샘플 포함.
- `data.zip`: 21,215,044,447 bytes. 전체 댓글 데이터; 서비스 추론에 필요하지 않음.
- `model.pth`: KcELECTRA 기반 계층적 분류 체크포인트.
- `model.py`: 18개 출력층을 갖는 모델 정의.
- `datasets.py`: 토큰화·전처리.
- `inference.py`: parquet 입력에서 예측 JSON을 생성하는 연구용 배치 추론.
- 입력의 `full_text`는 사용자명, 작성 지역, 기사 제목, 댓글 본문을 포함.
- 출력에는 troll/해외 연계 의심, 도덕적 비난·찬양, 표적 국가, BIO 근거 구절이 포함.
- README는 CUDA GPU 기반 참조 환경을 제시. CPU 추론 가능 여부와 성능은 미검증.
- API 기록의 라이선스는 CC-BY-4.0으로 표시. 배포 전 code.zip 내부 고지와 기반 모델 조건 확인 필요.

이 모델의 troll 판정을 일반적인 분란 조장 여부와 동일시하지 않는다.
특정 정치적 비판이나 분노 표현 자체를 차단 근거로 사용하지 않는다.
현재 서비스에는 연구 입력과 같은 신뢰할 수 있는 작성 지역·기사 제목 정보가 없으므로,
누락 필드 처리 및 국내 작성 글에 대한 적용 범위를 검증해야 한다.
사용자 입력에서 국적/정치 성향을 추정하거나 해외 연계 메타데이터를 꾸며 넣지 않는다.
기존 논문의 성능 수치를 이 서비스의 한국어/영어 성능으로 보고하지 않는다.

## 현재 미완료 항목

README 및 공개 파일 목록은 확인했다.
code.zip의 작은 바이트 범위 다운로드도 반복해서 504 또는 read timeout이 발생했다.
따라서 모델 클래스 생성자, 실제 체크포인트 형식/해시, 정확한 출력 키,
토크나이저/최대 길이/구절 오프셋을 아직 검증하지 못했다.
실제 가중치를 로드하거나 한국어·영어 실추론을 수행하지 않았다.
이 상태에서 가상의 출력 규격이나 임의의 키워드 규칙을 KAIST 모델로 구현하지 않는다.

## 후속 구현 위치와 순서

1. 명시적인 로컬 준비 명령으로 아티팩트를 다운로드하고 체크섬/버전을 고정.
   서버 시작이나 게시글 요청 중 자동 다운로드하지 않는다.
2. 공개 model.py/datasets.py/inference.py를 읽고 필요한 추론 경로만 어댑터로 분리.
   모델 정의와 가중치 로딩을 임의로 추정하지 않는다.
3. 기본 off인 검사 설정과 지연 로딩을 도입.
   off에서는 torch/transformers 로딩, 네트워크, 추가 DB 쓰기가 발생하지 않게 한다.
4. 모델을 프로세스당 한 번 로드하고 동시 추론, 입력 길이, 작업 큐를 제한.
5. `src/colorless/threads.py`의 쓰기 계획/권한 검증 후 DB commit 전에 검사.
   생성, 수정, 댓글, 답글에 적용하고 알림을 포함한 모든 mutation보다 먼저 차단.
   동일 작성 요청의 멱등 재시도 및 CAS 재계획으로 불필요한 재추론이 생기지 않게 한다.
6. 모델 판정과 운영 정책을 분리하고 라벨, 실제 근거 구절, 모델/정책 버전을 기록.
   본문과 소유 account 식별자는 일반 로그에 남기지 않는다.
7. 지원하지 않는 언어, 필요한 맥락 누락, 로딩 실패, 시간 초과의 상태를 명시.
   검사 실패를 통과 판정으로 기록하지 않는다.
8. 격리 SQLite와 인위적인 backend fixture로 차단 시 저장/알림 0건,
   수정 우회 방지, 권한, 재시도, 기본 off 동작을 검증.
9. 실제 체크포인트로 한국어·영어·혼용 및 비판/인용/풍자를 평가.
   영어 미지원 상태가 해결되기 전에는 한·영 검사 완료로 표시하지 않는다.
10. shadow 검증 후에만 enforce 활성화를 검토.
